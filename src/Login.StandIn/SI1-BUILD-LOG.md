## TL ruling TLD 16:48: F-SURR-LOGIN fix, 2026-11-04 (PT)
- Source: SSE2 probe report /tmp/sse2-fverify/F-SURR-LOGIN-PROBE.md, md5 183220008096d2eb3b07a9edae273024; probes /tmp/sse2-fverify/F-SURR-LOGIN-probes.jsonl (327), md5 9d7c39df51b6085a10b517dbb5e40403. Owner SSE2; SSE reviews; TL pushes.
- Cause: System.Text.Json reads names and strings lazily, so a lone/reversed surrogate escape (or invalid UTF-8) threw InvalidOperationException at first use, outside each caller's `catch (JsonException)`.
- Fix: one helper, StandInJson (Parse/ParseAsync/ParseObject[Async]/TryOptString). It parses, then force-decodes every key name and string value at every level; it catches only JsonException and InvalidOperationException and returns null. No `catch (Exception)`.
- Entry points now on the helper: Control.ReadObject (clock/freeze, clock/advance, faults, users, pcs); Control fixture load; SignIn agent/attest; SessionCap cage/actions body (HIGH-1, :180) and JWS payload nonce (HIGH-2, :191); Attestation.Check header and claims; Clients assertion header and claims. Not changed: Allowlist.cs (FROZEN), Tokens.cs (JsonWebTokenHandler, library), form-only endpoints.
- Behaviour: cage/actions with an undecodable body or JWS payload gets 403 {"error":"attestation_invalid"} plus auth.app_access.denied reason attestation_invalid (was 500, no event). Control freeze/advance/faults/users/pcs and agent/attest get 400 {"error":"invalid_request"}, no event (was 500). faults: a non-string outbox/device_registry value (object/array/number) gets 400; the node type is checked before GetValue. Valid escaped pairs are unchanged.
- Behaviour changes to note: (1) agent/attest with plain malformed JSON now gets 400 invalid_request (was 504). (2) An unknown nested field holding an invalid surrogate or invalid UTF-8 (users, pcs, agent/attest) now gets 400 (was 200 or 504), because the whole document is decoded.
- Regression: src/Login.StandIn/scripts/surr-regress.sh (static checks + 322 live probes in surr-regress.py + 5 Allowlist start-up cases = 327, one per probe row). Fix: 327/327, 0 x 5xx. Baseline 760521e: 219/327, 90 x 5xx. Mutations: revert HIGH-1 (M1) 18 fail; revert HIGH-2 (M2) 10 fail; catch widened to Exception (M3) caught by the static check; drop the force-decode (M4b) 94 fail; drop string decode (M4c) 41 fail. Removing the explicit key read was an equivalent mutant (enumerating a JsonObject decodes its names), so that line was dropped.
- Backlog (not done): **V11-UNKNOWN-FIELDS** (contract silent on unknown/nested fields in control and agent bodies). **ALLOWLIST-STRICT** (Allowlist.cs is frozen; an undecodable file already fails closed, but a raw-invalid-UTF-8 field outside `entries` still loads). **STANDIN-500-BODY** (contract/errors.md says nothing about HTTP 500 bodies).
