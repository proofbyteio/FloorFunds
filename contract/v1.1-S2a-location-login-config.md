### 3.2 `PUT /api/orgs/locations/{location_id}/login-config`

Permission: `org:location_login_method:write` [SRC: LD L171]. Headers: `If-Match: "<row_version>"` (required). Body: `$defs/login_config_write`. 200 returns the new view and new `ETag`.

**Concurrency choice: ETag / If-Match, not a body field.** Reasons: HTTP-native optimistic concurrency (RFC 9110 §13.1.1); keeps `row_version` out of the replacement body (one source of truth); proxies and clients already understand it. **Missing `If-Match` → 428 `precondition_required`** (RFC 6585 §3, "the origin server requires the request to be conditional"), chosen over 400 because it tells the client exactly what is missing and is distinct from a malformed body. `If-Match: *`, a weak tag, a list, or a non-integer → 400 `if_match_invalid`. Stale → 409 `concurrency_conflict` with `current_row_version` (MK9 conflict banner "Someone else changed this setting while you were editing…").

`secret_ref` in the body: **absent** = keep current; **string** = replace (rotation; recorded as `changed_fields` += `secret_ref`, no value); **null** = clear (only when switching to `database`). Switching an Entra location with a secret to `database` without `"secret_ref": null` → 422 `field_not_allowed` on `secret_ref` (no silent clearing).

## 4. Check order (writes; reads stop after step 4)

The caller is always checked before the value [TL Decision, S2a]. First failing step wins; later steps don't run.

| # | Check | Failure |
|---|---|---|
| 1 | **Authn**: valid bearer, `aud` backoffice-api | 401, no body, `WWW-Authenticate: Bearer`; **no event** (LD row 148 L750 pattern) |
| 2 | **Permission**: caller holds `org:location_login_method:write` (read: `org:V`) **through a built-in Super Admin or Partner Admin role**; the server ignores this permission on any custom, client or location role [SRC: LD L172] [TL Decision, S2a: full Admin-tier registry flag next slice] | 403 `forbidden`; event `not_admin` |
| 3 | **Location exists** (`auth.location_partner(location_id)` returns a row; §8.3) | 404 `not_found`; no event |
| 4 | **Partner scope**: Super Admin any; Partner Admin only `location.partner_id = token.partner_id` (create: body `partner_id`) — server query filter AND RLS [SRC: LD L173] | 403 `forbidden_scope`; event `wrong_partner` |
| 5 | **Precondition** (PUT): `If-Match` present / well-formed | 428 `precondition_required` / 400 `if_match_invalid`; no event |
| 6 | **Concurrency**: `If-Match` = current `row_version` (re-checked by the `UPDATE … WHERE row_version = $n` in the transaction) | 409 `concurrency_conflict` + `current_row_version`; no event |
| 7 | **Body**: valid JSON object | 400 `malformed_body`; no event |
| 8 | **Field validation** (§5.2), ALL field errors collected | 422 `validation_failed` + `fields[]`; no event, except `tenant_bound_elsewhere` → event `tenant_bound_elsewhere` (Super Admin too) |
| 9 | **Downgrade rule**: `mfa_required` true→false or `allow_db_fallback` false→true (vs the current row; on create vs "none", A-5) by a Partner Admin | 403 `not_super_admin`; event `not_super_admin` [Confirmed DEC-098; DEC-096] |
| 10 | **Reason rule**: Super Admin downgrade with `reason` absent/null/blank | 400 `reason_required`; no event [TL Decision, S2a] |
| 11 | Commit (§8.4); emit `auth.provider.changed` in the same transaction | outbox write fails → 500, nothing saved (fail-closed) [SRC: LD L184] |

Reads (GET) emit no events, including a 403 (ASSUMPTION A-19); the `operation` enum in §7.2 is create|update only.

Upgrades (`mfa_required` → true, `allow_db_fallback` → false) pass step 9 for both admins [TL Decision, LD L181, row 164]. A field that is unchanged is never a downgrade (a Partner Admin can edit `display_name` on a location whose fallback a Super Admin turned on).

**OPEN OQ-S2a-3 (scope response):** chosen **403 `forbidden_scope`** for an existing location of another partner, not 404. Reasons: `location_id`s are random UUIDs (not enumerable; the guessable thing is the slug, which this API doesn't take); the denied event needs the real target to attribute a cross-partner attempt; matches v1 `wrong_partner` (contract 7.4). Cost: a Partner Admin can learn that a UUID they already hold exists. Alternative: 404 for both missing and out-of-scope (event still audited). TL to confirm.

| Code | Rule |
|---|---|
| `required` | a required key missing (every editable key is required; send `null`/`[]`) |
| `unknown_field` | key not in the schema (incl. `row_version`, `slug`, `secret`) |
| `type` | wrong JSON type |
| `provider_kind_invalid` | not `database` / `entra` [SRC: LD L167] |

| `fallback_not_applicable` | `database` with `allow_db_fallback=true` (A-16; MK9 shows "Not used" for DB) |
| `partner_id_format`, `name_invalid` | create only |

## 8. Data: DDL intent (prose; no migration in this change)

Transaction DB (PostgreSQL), schema `auth` [SRC: LD L166]. Interim table set [TL Decision, S2a].

### 8.1 SSE-owned tables

- **`auth.location`**: `location_id uuid PK` (app-generated v4/v7), `partner_id uuid NOT NULL`, `slug text NOT NULL UNIQUE` (CHECK matches `^[a-z0-9](?:[a-z0-9-]{0,62})$`; server-generated ≥64 bits [SRC: LD L193]), `name text NOT NULL` (1..200). Index on `partner_id`. No `partners` table in S2a: `partner_id` is not an FK (OPEN OQ-S2a-8).
- **`auth.location_login_config`**, exactly the §4.1 columns [SRC: LD L167]: `location_id uuid PK REFERENCES auth.location ON DELETE RESTRICT`, `provider_kind text NOT NULL CHECK IN ('database','entra')`, `display_name text NOT NULL`, `entra_allowed_tenant_ids uuid[] NOT NULL DEFAULT '{}'`, `oidc_authority text NULL`, `oidc_client_id text NULL` (UUID text), `secret_ref text NULL`, `allow_db_fallback bool NOT NULL DEFAULT false`, `mfa_required bool NOT NULL`, `created_by uuid NOT NULL`, `created_at timestamptz NOT NULL`, `updated_by uuid NOT NULL`, `updated_at timestamptz NOT NULL`, `row_version bigint NOT NULL DEFAULT 1` (app increments by 1 per update; EF concurrency token; chosen over `xmin`, which is a wrapping 32-bit system column). CHECKs mirror §5.2: entra ⇒ `cardinality(tenants)=1 AND oidc_authority, oidc_client_id, secret_ref NOT NULL`; database ⇒ `cardinality(tenants)=0 AND oidc_* IS NULL AND secret_ref IS NULL AND NOT allow_db_fallback`. GIN index on `entra_allowed_tenant_ids` for the tenant rule.
- **`auth.location_login_config_change`**: `change_id uuid PK`, `location_id uuid NOT NULL REFERENCES auth.location`, `actor_user_id uuid NOT NULL`, `admin_type text NOT NULL CHECK IN ('super','partner')`, `reason text NULL` (≤500), `at timestamptz NOT NULL` [TL Decision, S2a]; plus (ASSUMPTION A-3/A-4) `change_kind text CHECK IN ('created','updated')`, `changed_fields text[] NOT NULL`, `before jsonb NULL`, `after jsonb NOT NULL` (the 4-key `audited_state`, never secrets), `row_version bigint NOT NULL`. ### 8.3 RLS and roles

- Roles (ASSUMPTION A-18 names): `cachd_owner` (owns `auth`, runs migrations, NOLOGIN in app paths), `cachd_admin_api` (this API), `cachd_login` (SSE2's login service). Neither app role owns any table; both `NOBYPASSRLS`. `ALTER TABLE … ENABLE` and `FORCE ROW LEVEL SECURITY` on `location`, `location_login_config`, `location_login_config_change`.
- Per request, inside the transaction: `set_config('app.admin_type', 'super'|'partner', true)` and `set_config('app.partner_id', '<uuid>', true)` (transaction-local, safe with pooling).
- Policy for `cachd_admin_api` on `auth.location` (and via `EXISTS` join on the other two): `USING/WITH CHECK (current_setting('app.admin_type', true) = 'super' OR partner_id = nullif(current_setting('app.partner_id', true), '')::uuid)`. Missing settings ⇒ no rows (fail closed). The server ALSO filters by `partner_id` in the query [SRC: LD L173].
- Two narrow `SECURITY DEFINER` functions (owner `cachd_owner`, `search_path` pinned, EXECUTE to `cachd_admin_api` only), needed because RLS hides other partners' rows: `auth.location_partner(location_id) → partner_id` (steps 3–4) and `auth.tenant_bound_elsewhere(tid uuid, partner_id uuid) → bool` (step 8).
- `cachd_login` policy: SELECT `USING (true)` on its RO tables (the login service is not partner-scoped).

### 8.5 Write transaction (fail-closed)

`BEGIN` → set RLS settings → `pg_advisory_xact_lock(hashtext('llc-tenant:'||tid))` when an Entra tenant is set (serialises the tenant rule against concurrent binds) → steps 3–10 → `UPDATE auth.location_login_config SET …, row_version = row_version + 1 WHERE location_id = $1 AND row_version = $2` (0 rows ⇒ 409) → `INSERT auth.location_login_config_change` → `INSERT audit_outbox` (`auth.provider.changed`) → `COMMIT`. Any failure rolls back all three [SRC: LD L184; AUD L141]. Denied events are written in their own short transaction (outbox only), then the refusal is returned.
